# Прототип робота на ESP32-CAM

Лёгкая версия робота на время, пока не приехали главное устройство и лидар.
Идея: на роботе только **глаза и моторы**, все вычисления — на ПК.

```
[ESP32-CAM] --MJPEG по WiFi--> [ПК: OpenCV + логика] --команды по UDP--> [ESP32-CAM] --> моторы
```

Когда придёт лидар и главный контроллер — вся логика на ПК уже будет
обкатана, поменяешь только источник данных.

## Структура

```
esp32-cam-prototype/
├── firmware_esp32/
│   └── firmware_esp32.ino   # прошивка: стрим камеры + приём команд по UDP
├── pc_host/
│   ├── robot_host.py        # ПК: приём видео, обработка, отправка команд
│   └── requirements.txt
└── README.md
```

## Что нужно из железа (предположения — поменяй под себя)

- **ESP32-CAM** (модуль AI-Thinker) + переходник для прошивки (FTDI/USB-TTL,
  либо плата-программатор ESP32-CAM-MB).
- **Драйвер моторов L298N** (или совместимый) и 2 мотора — дифференциальный
  привод (как у танка: рулим разницей скоростей колёс).
- **Питание 5V/2A** отдельным стабильным источником. ESP32-CAM капризна по
  питанию и греется — от слабого USB будет ребутиться.

## Схема подключения (по умолчанию в прошивке)

| Сигнал | GPIO ESP32-CAM | На L298N |
|--------|----------------|----------|
| Левый IN1 | 12 | IN1 |
| Левый IN2 | 13 | IN2 |
| Правый IN1 | 14 | IN3 |
| Правый IN2 | 15 | IN4 |
| Левый ШИМ (скорость) | 2 | ENA |
| Правый ШИМ (скорость) | 16 | ENB |
| GND | GND | GND (общий с питанием!) |

Замечания по пинам: у ESP32-CAM почти все ноги заняты камерой/PSRAM. Эти
шесть свободны и безопасны. **GPIO0 не трогай** — он нужен для прошивки.
SD-карту в прототипе не используем (пины пересекаются). Пины при желании
меняются вверху `.ino` в блоке настроек.

## Настройка и прошивка ESP32-CAM

1. Arduino IDE → Boards Manager → установи пакет **esp32** (Espressif).
2. Открой `firmware_esp32/firmware_esp32.ino`.
3. Впиши свои `WIFI_SSID` и `WIFI_PASS` вверху файла.
4. Выбери плату: **AI Thinker ESP32-CAM**. Включи PSRAM (если есть опция).
5. Подключи программатор, зажми загрузку (GPIO0→GND при ручном FTDI), залей.
6. Открой Serial Monitor на 115200 — там появится IP, например:
   ```
   IP-адрес: 192.168.1.50
   Стрим:    http://192.168.1.50:81/stream
   Команды:  UDP 192.168.1.50:4210  (формат "L R", -255..255)
   ```

Проверь стрим: открой `http://<IP>:81/stream` в браузере — должно показать видео.

## Запуск ПК-хоста

```bash
cd pc_host
pip install -r requirements.txt
python robot_host.py --host 192.168.1.50    # IP твоей ESP32-CAM
```

Откроется окно с видео. Управление с клавиатуры (окно в фокусе):

- **W / S** — вперёд / назад
- **A / D** — поворот на месте
- **ПРОБЕЛ** — стоп
- **M** — переключить ручной / авто-режим (авто = заглушка-логика)
- **Q / ESC** — выход (моторы глушатся)

Отладка без робота (видео с вебки ноутбука):

```bash
python robot_host.py --host 0.0.0.0 --source webcam
```

## Протокол команд (UDP, порт 4210)

Обычный текст, одна строка:

- `"L R"` — скорости левого и правого моторов, целые от −255 до 255.
  Примеры: `200 200` вперёд, `-200 -200` назад, `200 -200` поворот, `0 0` стоп.
- `"STOP"` — немедленная остановка.

**Failsafe:** если команд нет дольше 0.5 с, ESP32 сама глушит моторы — на
случай обрыва WiFi робот не уедет.

## Где писать свою логику

В `robot_host.py` — функция **`process_frame(frame, state)`**. На вход кадр
(numpy BGR), на выход `(left, right)`. Сейчас там заглушка: робот
поворачивается к самой яркой точке кадра — просто чтобы показать, что
замкнутый контур «камера → обработка → моторы» работает. Меняй на детекцию,
навигацию, следование за объектом и т.д.

## Ограничения (честно)

- **Задержка.** MJPEG по WiFi — обычно 100–300 мс. Для медленного робота
  (едет, осматривается, объезжает) нормально. Для быстрых реакций (баланс,
  гонки) — нет.
- **Нет глубины.** Одна камера не даёт расстояний как лидар. Для прототипа
  пайплайна это ок; точную геометрию добавишь с лидаром.
- **Один клиент стрима.** Прошивка отдаёт стрим одному потребителю за раз
  (хост ПК). Этого для задачи достаточно.
