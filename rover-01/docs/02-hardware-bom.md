## Карта подключений

```
                 ┌───────────────────┐
   RPLIDAR ──USB─┤                   │
                 │  Jetson Orin Nano  │
   (Wi-Fi/Eth) ──┤  (ROS2, Ubuntu)    │
                 └─────────┬─────────┘
                           │ USB (micro-ROS, serial)
                 ┌─────────┴─────────┐
   IMU BNO055 ─I2C┤      ESP32         ├─PWM/DIR─► L298N ─► моторы (борт L / борт R)
   энкодеры ──GPIO┤                   │
   ав.кнопка ─GPIO┤                   │
   бампер ────GPIO┤                   │
                 └───────────────────┘
```

## Питание — частая причина «мистических» багов

- Моторы и L298N питать **отдельной** линией от логики (ESP32/Jetson). Общая только земля (GND).
- Бросок тока от моторов проседает напряжение → ESP32 ребутится в самый неподходящий момент.
- Jetson капризен к питанию: недобор по току → троттлинг и падения нод. Дать стабильные 5V с запасом.

## Про энкодеры — почему «докупить», а не «опционально»

Без энкодеров нет одометрии с колёс. Лидарная одометрия + IMU позволяют **начать** тесты,
но дрейфуют и плохо держат поворот в пустых/симметричных помещениях.
Разница ощутимая: «демка ездит по комнате» (можно без энкодеров) против
«робот стабильно навигируется» (нужны энкодеры).

Что брать: на простые DC-моторы без энкодерного вала ставят **магнитные энкодеры** —
датчик Холла + магнитный диск на ось колеса. Дёшево, заводится на GPIO ESP32 (прерывания).
Минимум — по одному на каждый борт (skid-steer); лучше — на все 4 колеса.
