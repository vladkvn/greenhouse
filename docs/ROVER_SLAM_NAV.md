# Ровер-фолловер: карта (SLAM) и езда в точку — bring-up

Статус: **код готов, не проверен на железе** (Jetson был недоступен при написании).
Этапы A (телеоп) и читалка IMU — сделаны ранее. Здесь — этапы C (SLAM-карта) и D (goto).

## Архитектура

```
лидар (360 бин) ─┐
курс BNO085 ──────┼─> SlamMapper (BreezySLAM RMHC) ─> карта + поза ─┐
                  │                                                  ├─> /map.png (веб)
                  └─> (поворот = прайор из IMU, смещение = scan-match)
клик по карте ─> Navigator (A* план + pure-pursuit) ─> команда моторам (режим goto)
телеоп с пульта ─────────────────────────────────────> команда моторам (режим mapping)
```

Модули: `follow_me/slam.py` (обёртка BreezySLAM), `follow_me/navigation.py`
(A* `plan_path` + `pursuit_command` + `Navigator`), интеграция в `main.py`,
веб — `/map.png`, POST `/goal?col=&row=`, поле «Поза» и кликабельная карта.

SLAM крутится непрерывно (троттлинг `slam_update_period_s=0.15`), карта строится в режиме
`mapping` (катаешь телеопом), используется в `goto`.

## Установка зависимостей на Jetson (в venv)

```bash
~/greenhouse/.venv/bin/pip install breezyslam adafruit-blinka adafruit-circuitpython-bno08x
```

- `breezyslam` — C-расширение, нужны build-tools (`sudo apt install build-essential python3-dev`).
- `adafruit-blinka` — определяет плату Jetson сам; проверить: `python -c "import board"`.
- Если что-то из этого не встало — follow_me всё равно запустится (модули опциональны:
  `slam.available()==False`, IMU-курс=None), просто без карты/курса.

## Подключение BNO085 к Jetson (40-пиновый гребень)

| BNO085 | Jetson pin |
|---|---|
| VIN | pin 1 (3.3V) |
| SDA | pin 3 |
| SCL | pin 5 |
| GND | pin 6 |

I2C-шину гребня проверить: `i2cdetect -y -r <bus>` (датчик на 0x4A). Номер шины для board.SDA/SCL
уточнить (`i2cdetect -l`); Blinka использует дефолтную I2C гребня (pins 3/5).

## Калибровка на железе (ВАЖНО, проверить по порядку)

1. **IMU курс**: режим любой, поворачивай робота — `/state.imu_yaw` должен плавно идти
   0..360. Знак (по/против часовой) запомнить.
2. **SLAM-поза vs реальность**: режим `mapping`, проедь вперёд 1 м — на карте робот
   (зелёная точка) должен поехать; стены проявиться. Если карта «разъезжается» при
   поворотах — знак `dtheta` в `slam.py` (`_angle_diff_deg(imu_yaw, last)`) инвертировать.
3. **Ориентация карты/позы**: если поза по x/y зеркальна — поправить `world_to_pixel`
   (`slam.py`). Клик и маркер робота используют один трансформ, так что цель визуально
   сойдётся; важно чтобы pure-pursuit рулил в верную сторону.
4. **Знак pure-pursuit**: режим `goto`, кликни точку прямо перед роботом — должен поехать
   К ней. Если рулит в противоположную сторону — поменять местами `left`/`right` в
   `pursuit_command` (`navigation.py`) ИЛИ знак `err`.
5. **Стоп по препятствию**: едет в точку, поставь препятствие на пути ближе
   `nav_obstacle_stop_m=0.5` — должен встать. (Лидар 0° = вперёд.)

## Тюнинг (config.py)

- `map_size_pixels=500`, `map_size_meters=10` → 2 см/пиксель. Больше помещение — увеличь метры.
- `robot_radius_m=0.25` — раздув препятствий под габарит.
- `lookahead_m=0.6`, `nav_speed=160`, `nav_turn_gain=2.0` — поведение pure-pursuit.
- `slam_scan_rate_hz=5.5`, `slam_no_detection_mm=12000` — модель RPLIDAR A1.

# СОСТОЯНИЕ НА КОНЕЦ СЕССИИ (2026-06) — для следующих сессий

## Что РАБОТАЕТ (проверено на железе)
- Веб-интерфейс `http://192.168.1.132:8090` (через systemd `followme.service`, автозапуск).
- Режимы: idle / follow (следование за человеком, с --drive) / mapping (телеоп WASD+пульт) /
  goto (см. ниже, не докручен).
- Лидар RPLIDAR A1 (/dev/ttyUSB1 CP2102, by-id), фьюжн камера+лидар, стоп на 1 м.
- IMU BNO085 — НА JETSON по I2C (/dev/i2c-7, 0x4A), прямыми джамперами (НЕ шлейфом!),
  курс читается, `imu.py`.
- **Hector SLAM** (`hector.py`, `slam_backend="hector"`) — scan-to-map matching + IMU-прайор
  поворота + ШИМ-одометрия. Вдоль стен карта строится хорошо (тонкие линии, держится).
- Телеоп с плавной рампой моторов, многоклавишные дуги (W+D), deadman 0.6с.

## ОТКРЫТЫЕ ВОПРОСЫ (разбирать дальше)
1. **Hector теряет трек вокруг ОДИНОЧНОЙ КОЛОННЫ** — вырожденный случай (круглый объект
   не фиксирует позицию при кружении → поза плывёт → колонна размазывается/исчезает).
   Вдоль стен ок. Фундаментально лечится: больше признаков / энкодеры / loop-closure.
   Снизили `hector_free_gain` 0.15→0.08 для стойкости объектов.
2. **goto НЕ откалиброван под систему координат Hector.** У Hector перёд = `theta`
   (в отличие от BreezySLAM theta+180). Выставлено: `nav_heading_offset_deg=0`,
   стрелка курса рисуется вдоль +theta, `nav_turn_invert=False` (флипнут под Hector,
   НЕ проверен на железе). Калибровать замером: проехать прямо вперёд, сверить
   направление смещения позы с theta (как делали для BreezySLAM).
3. **goto ломает карту**, если едет криво (кружит) на скорости. Сделать goto медленным и
   ровным (верный курс) → его движение станет для Hector таким же безобидным, как телеоп.
   `nav_speed=140` возможно много для трекинга — снизить.
4. **`odom_speed_full_mps=0.35` не откалибрована** (энкодеров нет). Замер: проехать
   измеренный 1 м, сверить смещение робота-маркера на карте.
5. **Энкодеры** — обсуждалось как путь к «пылесосному» качеству карты (точная одометрия).
   Без них Hector — потолок на одном лидаре.

## КЛЮЧЕВЫЕ ГРАБЛИ (чтоб не повторять)
- BreezySLAM theta ≠ Hector theta (разные конвенции) → nav-калибровку (offset/turn_invert)
  и стрелку надо переделывать при смене бэкенда.
- Hector multi-res: MAX-pool (не mean — стена усреднялась в ничто → дрейф 9см на месте).
- Hector расходился на реальных данных → защиты: LM-демпфирование, отброс скачка, warmup,
  клэмп. IMU-прайор поворота — обязателен (без него первый поворот рвёт карту).
- A* для goto — в ФОНОВОМ потоке + на загрублённой сетке (nav_plan_scale=4), иначе
  GIL/тяжёлый A* роняет FPS до 4.
- Деплой: `scp follow_me/*.py luki@192.168.1.132:~/greenhouse/follow_me/` +
  `sudo systemctl restart followme`. Сеть капризная — scp может побить файл null-байтами
  (проверять компиляцией на Jetson). IMU/ESP по USB иногда отваливаются.
