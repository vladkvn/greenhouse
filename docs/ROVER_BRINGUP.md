# Ввод ровера в эксплуатацию (трек B) — пошаговый runbook

Весь «мозг» (режимы, навигация, следование, карта, зарядка, keep-out) уже проверен в
симуляции и собран в боевые адаптеры `src/greenhouse/adapters/jetson/`. Этот документ —
порядок подъёма на железе: каждый шаг даёт конкретную команду и критерий «работает».

Архитектура и обоснование — в [ARCHITECTURE_ROVER.md](ARCHITECTURE_ROVER.md). Адреса/железо —
в памяти проекта (`rover-follower-deploy`).

## 0. Что измерить на конкретном шасси (заполнить в `JetsonConfig`)

Все эти значения помечены `# CALIBRATE` в [`adapters/jetson/loop.py`](../src/greenhouse/adapters/jetson/loop.py)
(класс `JetsonConfig`). Без них стек поедет неверно.

> **Печатный комплект:** [`calibration/rover_calibration_sheets.pdf`](calibration/rover_calibration_sheets.pdf)
> — 3 листа A4 (угломер-центровка, лист замеров, таблица `JetsonConfig`). Печатать **100%**
> (без «вписать в страницу»), проверить по линейке 100 мм на листе 1. Пересобрать:
> `uv run --no-project --with reportlab python docs/calibration/generate_sheets.py`.

| Параметр | Что это | Как получить |
|---|---|---|
| `lidar_forward_bin_deg` | какой сырой бин RPLIDAR смотрит ВПЕРЁД | шаг 1 (калибровка угла) |
| `lidar_clockwise` | направление вращения лидара | шаг 1 |
| `lidar_masked_sectors` | секторы, где лидар видит свой корпус (self-hit) | осмотр + шаг 1 |
| `wheel_base_m` | колея (расстояние между бортами) | рулетка |
| `max_linear_m_s`, `pwm_max` | связь скорость↔ШИМ | шаг 2 (калибровка привода) |
| `pwm_min_move` | ШИМ, ниже которого мотор не крутится | шаг 2 |
| `robot_radius_m` | описанный радиус корпуса + 5 см | рулетка (полудиагональ) |
| `hfov_rad` | горизонтальный FOV камеры | паспорт объектива |
| `use_imu` | True когда заведён реальный IMU | шаг 4 |

Ещё нужно решить по железу: датчик заряда (ADC ESP32 / INA219 → `BatterySource`) и
механизм дока (воронка / ArUco / магнит) — для шагов 8 и 10.

## Предусловия

1. Прошить ESP32 (`follow-me/firmware_esp32/`) — статический IP, UDP 4210, failsafe 0.5 с.
2. Код на Jetson: репозиторий доступен, боевой пакет `follow_me` на `PYTHONPATH`
   (`~/greenhouse/follow_me`), `greenhouse` ставится из `src/` (или `PYTHONPATH=src`).
3. Прогнать тесты ядра (всё, что не требует железа, должно быть зелёным):
   ```bash
   PYTHONPATH=src uvx --with pydantic --with pytest pytest tests/ -q
   ```

## Шаг 0 → 1. Телеоп + калибровка лидара (инкремент 0)

Проверяем самый нижний шов — `Twist2D → ESP32` и конвенцию углов лидара — БЕЗ локализации.

```bash
python -m greenhouse.adapters.jetson.teleop \
  --esp32 192.168.1.50 --lidar-port /dev/ttyUSB0 \
  --forward-bin-deg 0 --linear 0.15 --angular 0.6
```
**Калибровка угла лидара:** поставь препятствие строго ПО КУРСУ (~1 м). В выводе телеопа
поле `fwd` должно показывать его дистанцию. Если не показывает — крути `--forward-bin-deg`
(и/или добавь `--ccw`), пока препятствие по курсу не попадёт в луч 0. Запиши в
`JetsonConfig.lidar_forward_bin_deg` / `lidar_clockwise`.

**Готово, если:** робот едет вперёд/крутится по команде, при обрыве цикла моторы сами
встают (failsafe), `fwd` соответствует препятствию по курсу.

## Шаг 2. Калибровка привода (скорость ↔ ШИМ)

Без энкодеров связь команда→скорость снимается на стенде:
- проезд: командуй фикс. `--linear` N секунд, померь рулеткой/лидаром пройденный путь →
  реальная м/с при текущем `pwm_max`. Подгони `max_linear_m_s`/`pwm_max`, чтобы совпало.
- порог: уменьшай скорость, пока мотор не перестаёт крутиться → `pwm_min_move`.
- поворот: команду `--angular`, замерь по лидару угол за время → проверь `wheel_base_m`.

**Готово, если:** заданная `Twist2D` даёт предсказуемую скорость/поворот (грубо ±20 %).

## Шаг 4. Локализация без энкодеров (инкременты 5 + 12)

`DeadReckonOdometry` (интеграл команды) + scan-match; курс — с IMU, если есть.
Собери робота и погоняй цикл, наблюдая позу в логе:
```bash
python -m greenhouse.adapters.jetson.runner --rate 10 \
  --esp32 192.168.1.50 --lidar-port /dev/ttyUSB0 --forward-bin-deg <из шага 1>
```
По умолчанию робот стоит в IDLE (безопасно). Для проверки локализации временно подай
карту (`build_jetson_robot(grid=...)`) — поза в телеметрии должна держаться на
структурированной местности и честно уходить в `localization_lost` на бедном скане.

**IMU:** когда заведёшь реальный IMU (замена `ZeroImu` на драйвер `ImuSource`), поставь
`use_imu=True` — курс пойдёт с гироскопа (важно против проскальзывания скид-стира).

**Готово, если:** поза стабильна при наличии геометрии; при потере — стоп, а не «слепая езда».

## Шаг 5. Следование с памятью (флагман «за угол»)

Зрение (`JetsonTargetDetector`) даёт курс на человека, лидар — дальность. `FollowingBehavior`
ведёт под-FSM TRACKING → (за угол) GOTO_LAST_SEEN → SEARCH → IDLE_WAIT.
```bash
python -m greenhouse.adapters.jetson.runner --rate 10 --follow   # стартует в FOLLOWING
```
Зрение по умолчанию — ленивый YOLO поверх `follow_me` (нужны `models/yolo11n.engine` + камера).
Проверь сценарий: иди, заверни за угол — робот должен доехать в точку последнего видения,
осмотреться и, не найдя, встать в ожидание; появись снова — мгновенно продолжит.

**Готово, если:** держит дистанцию, объезжает по лидару, корректно отрабатывает «за угол».

## Шаги 6–8. Карта, навигация на точку, keep-out, зарядка

- **MAPPING (6):** собери робота с `mapper=EvidenceGridMapper(meta=...)`; команда
  `StartMapping` запускает frontier-исследование; по завершении сохрани карту (`FileMapStore`).
- **NAVIGATING + keep-out (7):** перезапусти с загруженной картой (`grid=...`). Команда
  `GoTo(goal)` едет с объездом и габаритом. Оператор ставит зону командой
  `EditKeepout(op="add", zone=...)` — путь её обходит (полуоткрытая местность: очерти
  безопасный периметр без физических стен).
- **CHARGING (8):** задай `dock=Pose2D(...)` и `BatterySource`; `GoCharge` (или авто-preempt
  Supervisor при низком заряде) везёт на док и держит до полного.

Все три режима гоняются ОДНИМ оркестратором — это те же поведения, что зелёные в sim
(`tests/test_*_behavior.py`, `test_orchestration_integration.py`).

---

## Шаги 9–10. Failsafe и автодокинг

- **Failsafe (9):** три уровня уже в коде — ESP32 watchdog 0.5 с, `DriveWatchdog` (deadman
  0.3 с в `JetsonMotion`), `Supervisor` (потеря локализации/связи/низкий заряд). Проверь
  каждую ветку: выдерни питание ESP32 на ходу, заглуши процесс, опусти заряд.
- **Автодокинг (10):** последние ~0.5 м точности scan-match не хватает — нужен терминальный
  доводчик (ArUco-маркер через камеру, обёрнутый как `TargetDetector`, или мех. воронка).
  Отдельный риск, делается последним; до него — причаливание вручную.

## Точки расширения (когда понадобится)

- **Новый датчик** того же рода → новый класс за тем же `Protocol` (`LidarSource`/
  `OdometrySource`/`ImuSource`/`BatterySource`/`TargetDetector`), подменить в `build_jetson_robot`.
- **Новый датчик нового рода** → новый DTO + `Protocol` в `sensing/interfaces.py`,
  потребитель инжектит его в конструктор (эталон — `ImuFusedLocalizer(imu=...)`).
- **Новый режим** → `registry.register(NewBehavior(...))` + член `RobotMode` + при нужде
  команда в union `Command`. Ядро и оркестратор не трогаются.
- **Источник команд оператора** (UDP/CLI/веб) → дёргает `robot.orchestrator.handle(command=...)`;
  пока в `runner.py` только стартовый флаг `--follow`.
