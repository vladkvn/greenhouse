# Двухуровневый сон ровера — план (делаем отдельной сессией)

Цель: снизить потребление на простое, **не теряя состояние** (карта/поза/локализация) —
робот просыпается и едет «как ни в чём не бывало». База сейчас ~10 Вт (весь стек).

## FSM (узел `idle_manager`)

```
ACTIVE ──(нет активности T1, ~60с)──► LIGHT_SLEEP ──(ещё T2, ~10мин)──► DEEP_SLEEP
  ▲                                        │                               │
  └──── активность / кнопка ───────────────┘                               │
  └──────────── ТОЛЬКО кнопка (аппаратный wake) ───────────────────────────┘
```

- **Активность** (сброс таймера): новый Nav2-goal, `/follow/*`, ручной `/cmd_vel`, движение (`/odom`),
  кнопка пульта (`/rover/mode`, `/rover/key`).
- Из **LIGHT** будит любая активность (ROS жив). Из **DEEP** — **только кнопка** (ROS в suspend,
  сеть/топики не разбудят) → нужен аппаратный wake-пин.

## Уровень A — LIGHT_SLEEP (~5 Вт, состояние в RAM, бесшовно)
Действия при входе:
- стоп мотора лидара (сервис/рестарт `rplidar_scan_node`);
- `nvpmodel` → низкий режим (+ понизить клоки);
- пауза Nav2 (lifecycle deactivate) — slam оставляем (карта в памяти); YOLO уже по флагу;
- моторы уже в выбеге (deadman привода).
Пробуждение: старт лидара, `nvpmodel` → полный, активировать Nav2. ~секунды, состояние целое.

## Уровень B — DEEP_SLEEP (~1–2 Вт, RAM сохраняется, wake кнопкой)
Перед сном:
- **сериализовать карту** slam_toolbox на диск + сохранить позу (страховка на случай плохого resume);
- корректно закрыть/подготовить serial-узлы к suspend.
Сон:
- `systemctl suspend` (suspend-to-RAM, RAM держится).
Пробуждение (кнопкой):
- ESP32 дёргает **wake-GPIO** Jetson;
- resume из RAM → **обработать скачок времени** (сброс TF-буфера / таймеров Nav2 или рестарт стека);
- **переоткрыть serial** (VESC/лидар/ESP32 переэнумерировались по USB);
- восстановить `nvpmodel`/лидар/Nav2; при плохом состоянии — загрузить карту и релокализоваться.

## Задачи (объём сессии)
1. **`idle_manager`** — FSM + мониторинг активности + вызовы действий (subprocess: nvpmodel, suspend,
   lidar, Nav2 lifecycle). Интеграция с `/rover/mode` (кнопка = форс-сон/пробуждение).
2. **Resume-стойкость serial-узлов** (`vesc_diff_drive`, `esp32_sensor_bridge`, `rplidar_scan_node`,
   `bno085_imu_node`) — переоткрытие порта при обрыве (нужно для B).
3. **Аппаратный wake**: найти валидный wake-пин Orin; прошивка ESP32 «кнопка → импульс на wake-пин».
4. **Права**: passwordless sudo на `nvpmodel` и `systemctl suspend` (sudoers) или привилегированный хелпер.
5. **Персист карты/позы**: serialize/deserialize slam_toolbox вокруг deep sleep.

## Параметры (robot.yaml / idle_manager)
- `T1` (ACTIVE→LIGHT), `T2` (LIGHT→DEEP);
- режимы `nvpmodel` (активный/низкий), номер wake-GPIO;
- список топиков-активности.

## Уточнить в начале сессии
- Точная модель Jetson/носителя (wake-пины и nvpmodel-режимы зависят от неё).
- Ёмкость батареи и типичное время простоя → пороги `T1`/`T2` и стоит ли уровень B.
- Готовность модуля `esp32-sensor-remote` (он же будильник для DEEP).

## Реализм
- Езда моторами ест несравнимо больше простоя → сон окупается, только если робот **подолгу паркуется**.
- От 10 Вт: A ≈ ~5 Вт (×2 к standby, легко), B ≈ ~2–3 Вт (×4, но с доработкой serial+wake).
