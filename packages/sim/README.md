# sim

## Purpose

Пакет **`fleet-sim`**: простая **2D-симуляция** нескольких комнат на плоскости (стены как отрезки, связанные коридоры/проёмы в общей стене) и mock-реализации `fleet_contracts` без ROS (`LidarSource`, `MotionController`, `Localizer`, `CameraSource`, `PersonDetector`).

Численный интегратор и рейкаст лидара используются в демо-сценарии: объезд центроидов комнат с ограничением скорости по «ближайшей дистанции вперёд», затем обнаружение цели-силуэта и следование к точке по **пути из A*-плана на сетке** с учётом **вписанного кругового отпечатка** робота. Препятствия — те же **`PolygonWorld.walls`**, по которым строится лидарайкаст: диск робота не должен **пересекать** ни один из этих отрезков (а центр — оставаться внутри объединения прямоугольников комнат); хорды маршрута при упрощении проверяются так же через выборку вдоль хорды.

## Interface

- Реализации лежат в [`src/fleet_sim/mocks/`](./src/fleet_sim/mocks/), помощники планирования в [`footprint.py`](./src/fleet_sim/footprint.py) и [`grid_nav.py`](./src/fleet_sim/grid_nav.py).
- Топология мира по умолчанию: **`greenhouse_parallel_rows_world`** — длинные параллельные ряды («проходы парника») с полосами-грядками между ними и выровненными проёмами; для регрессий остаётся компактная схема **`three_rooms_line_world`**.
- Точки входа: `fleet-sim-demo` (консоль), `fleet-sim-viz` ([`demo_visual.py`](./src/fleet_sim/demo_visual.py) — окно matplotlib).

## Dependencies

- Python ≥ 3.11
- Пакет **`fleet-contracts`** из [`packages/contracts`](../contracts/)
- Для окна: **`matplotlib`** (extras `viz` или `dev`, см. ниже)

## Установка и запуск

Из корня монорепозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e packages/contracts
pip install -e "packages/sim[viz]"     # matplotlib + консольные команды
# или: pip install -e "packages/sim[dev]"  # то же + инструменты ruff/mypy
ruff check packages/sim/src && python -m mypy packages/sim/src   # при [dev]
fleet-sim-demo
```

Только консольное демо (`fleet-sim-demo`) не требует matplotlib, но установка `[viz]` добавляет и его.

**Окно с картой** — стены, редкие лучи лидара (бирюза, вращаются с роботом), фиолетовая **линия маршрута** в режиме follow, зелёный треугольник робота, красная цель следования (**перетаскивайте мышью**, координаты ограничены свободным пространством мира):

```bash
fleet-sim-viz
```

Нужен доступ к дисплею. При проблемах бэкенда: `export MPLBACKEND=TkAgg` (Linux/macOS часто не требуется).

## Габариты и связь с «боевым» стеком

- Задаётся **радиус вписанного диска** (`SimState.robot_inscribed_radius_m`; по умолчанию — класс [`ExploreFollowDemo`](./src/fleet_sim/demo_runner.py)). Это же значение используется для проверки **пересечения диска с сегментами `PolygonWorld.walls`** и для ограничения центра робота объединением прямоугольников комнат; реализации — функции **`footprint_circle_navigable`** и **`chord_footprints_navigable`** в [`footprint.py`](./src/fleet_sim/footprint.py), вызываемые из **`grid_nav`** и **`simulation_step`**.
- На реальном роботе в ROS 2 / Nav2 обычно задают **polygon footprint** и **слои costmap (inflation, clearing)**. Принцип переноса из симулятора: **планирование и проверки коллизий должны согласовывать одну и ту же геометрию робота занятости** (диск здесь — консервативное упрощение прямоугольного корпуса).

## ROS topics / MQTT

Не используется; при интеграции с роботом контракты те же, что и на борту.

## Ограничения MVP

- Планирование использует **круговый отпечаток**, ориентация корпуса в глобальной сетке явно не крутится; узкие проёмы в реальности лучше валидировать полигоном footprint и costmap или графом порталов.
- Стены имеют **нулевую толщину** в симуляторе препятствий; между лидаром, планом и столкновениями они согласованы как один и тот же набор сегментов `walls`.
- Локализация — **истина симулятора**, не SLAM.
